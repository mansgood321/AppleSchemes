# AppleSchemes · доработка витрины и админ-панели без изменения Supabase

Это версия проекта для **существующего** Supabase, URL и публичный ключ перенесены из исходного `AppleSchemes-main (2).zip` в `supabase-config.js`. Секретных ключей в клиентском коде нет. Никакие SQL-файлы, миграции, RLS или Edge Functions здесь не создаются и не изменяются.

## Что заменить в GitHub

Из папки `AppleSchemes-main` замените только **`store.js`**, **`admin.js`**, **`admin.html`**, **`style.css`** и при необходимости **`supabase-config.js`** (если в GitHub сейчас версия с `REPLACE_WITH_NEW_PROJECT`). Остальные существующие файлы не трогайте. Полный ZIP проекта прилагается как дополнительная копия.

## Использование

1. Откройте `admin.html`, войдите под существующей учётной записью администратора.
2. В разделе «Категории» создайте раздел, например **iPhone 18**. Его модельный ряд создаётся через «Товары».
3. Создайте товар «iPhone 18 Pro», загрузите фото. Ниже откройте «Характеристики и цены».
4. Добавьте нужные поля по одному: `memory` (Память), `sim_type` (Тип SIM), `color` (Цвет) или `screen_size`, `chip`, `ram`, `storage`, `case_size`, `band`, и любые дополнительные ключи формата `a_z_123`.
5. Откройте «Добавить конфигурацию», заполните значения, цену, валюту и наличие. Нажмите «Создать конфигурацию». Для другой комбинации создайте новую строку.
6. Витрина в `index.html` показывает категории → модели → только характеристики из существующих вариантов; цена появляется только при единственном точном совпадении. Заказ использует прежнюю функцию `telegram-order`.

### Ограничения существующей схемы (без изменений SQL)

- `product_variants.attributes` хранит произвольные ключи и значения, поэтому параметры для каждой модели могут отличаться.
- У таблицы `products` нет отдельного поля для определений характеристик модели. Новые поля в редакторе — **черновик текущей страницы**: они сохраняются в базе только как значения созданной или отредактированной конфигурации. После перезагрузки данные восстанавливаются из сохранённых конфигураций, но произвольное отображаемое имя нового ключа может вернуться к его техническому имени. Общие красивые подписи можно настроить в `categories.attributes_schema`.
- У существующей категории `attributes_schema` общая для категории, а не товара. Список дополнительных вариантов фактически определяется записью каждой конфигурации.
- Предыдущий `excel.js` использует SQL RPC `import_catalog_excel` и при экспорте обращается к `products.import_key`, которого **нет** в приложенном описании существующей схемы. Поэтому работу старого импорта/экспорта Excel на исходной базе **нельзя гарантировать** без такого RPC или изменения клиентской логики. В этом этапе Excel-модуль не изменён.
- Функция Telegram не поставлялась в экспорте старого Supabase; успешная реальная отправка заказа требует проверки в действующем проекте.
- Сопоставление дубликатов в админ-панели сделано на клиенте; параллельные изменения несколькими администраторами и уникальность на уровне сервера без соответствующих ограничений базы полностью не гарантируются.

## Проверка после обновления

1. **Категории:** зайдите в админку, убедитесь, что прежние категории отображаются, настройте порядок/видимость только если нужно.
2. **Товары:** откройте имеющуюся модель, убедитесь, что фото, цена и характеристики сохранены.
3. **Тестовая модель:** создайте отдельный временный товар и добавьте две конфигурации с разными цветами и ценами. Для теста используйте собственные примерные значения, не изменяйте реальные цены.
4. **Витрина:** откройте тестовую модель, выберите цвет и проверьте точную цену. Попробуйте комбинацию, которой нет в базе: заказ не должен предлагаться.
5. **Заказы:** отправьте один тестовый заказ и проверьте его доставку в Telegram (сохранён прежний вызов `telegram-order`).
6. **Мобильная версия:** проверьте экран 375px и 390px, переключение категорий и открытие конфигураций.
7. После проверки удалите временный товар в админке, если он больше не нужен.

**Важно:** локально проверены синтаксис JS и автономная логика витрины; выполнение запросов к реальному Supabase, отправка в Telegram и RLS не были проверены. Если в вашем GitHub URL проекта уже актуален, его не заменяйте.
